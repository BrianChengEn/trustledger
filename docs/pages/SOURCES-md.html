Jev

  • Introduction：Jev 是 decision model；POST /api/v1/systemone/；每次最多 20 個 questions；問題類型為 noul、choice、score。
  • Authentication：Authorization: Bearer 或 x-api-key；key 僅可放 server；建議每個環境一把 key。
  • Decisions contract：state、questions、可選 model；optional Idempotency-Key；回應含 id、model_version、answers、usage、latency_ms。
  • Question types：choice.criteria 是 label → description object；score.criteria 是由低到高的 array；score 回傳 decimal。
  • Models：已列出 jev-1.13 與 rolling jev-latest。MVP 鎖定 jev-1.13，避免比賽中行為漂移。

Backboard

  • Authentication：X-API-Key；key 只能存在 server-side environment variable。
  • Architecture：Assistant 包含 threads；Memory 位於 assistant scope，會跨同 assistant 的 threads 使用。
  • Send Message：POST https://app.backboard.io/api/threads/messages；常用欄位為 content、thread_id、assistant_id、memory、stream。
  • Memory：memory="Auto" 寫入與讀取、Readonly 只讀、off 停用；提供 list/add/search/get/update/delete memory endpoints；memory operation 可能非同步。
  • Create Assistant：POST /assistants，至少需要 name；可設定 system_prompt 與 custom memory prompts。

安全推論： 因 memory 是 assistant-scoped 且跨 threads，共用一個 assistant 給多位終端使用者可能造成跨使用者記憶混用。MVP 僅使用單一合成 demo user；未來多使用者版應採每位使用者獨立 assistant，或先取得 Backboard 明確支援的 isolation design，再做 adversarial test。這是架構推論，不是 Backboard 的合規保證。

Capital One Nessie

  • Nessie 官方文件：Nessie 是 banking simulation REST API；資源包含 customers、accounts、deposits、withdrawals、transfers、purchases、bills、loans、merchants、ATMs、branches、enterprise。
  • Nessie Getting Started：GitHub login 取得 API key；key 以 key query parameter 傳入；enterprise endpoints 只讀。
  • 2026-10-17 直接檢查官方互動文件可見：GET /customers、GET /customers/{id}/accounts、GET /accounts/{id}/bills、GET /merchants 等；Authentication 頁顯示 OpenAPI 1.0.0 / OAS 3.0。
  • 官方 Quick Start 顯示 POST /customers、POST /customers/{id}/accounts、POST /accounts/{id}/deposits、POST /accounts/{id}/transfers。

Nessie 不一致與保守決策

同日官方 OpenAPI operation list 的 purchases 區只顯示 GET/PUT/DELETE /purchase/{purchase_id}，但舊 SDK/文件常見 /accounts/{id}/purchases；Quick Start 也顯示 create transfer，但 operation list 的 Transfers 區未完整顯示 create/list。這可能是網站/OpenAPI 更新不同步。

因此本套件：

  1. 不把未確認的 list/create purchase/transfer endpoints 寫成必定可執行的程式。
  2. Demo 核心交易流以合成 fixture 為準。
  3. Nessie integration 先做官方頁面當下可見的 read endpoints 與 health probe。
  4. 活動現場若 sponsor mentor 確認新 contract，再更新 adapter；不要讓 contract investigation 阻塞 vertical slice。

工具鏈與安全參考

  • Vite Getting Started：目前要求 Node.js 20.19+ 或 22.12+；react-ts template 可用。
  • FastAPI Tutorial：建議 pip install "fastapi[standard]"；Python 3.10+ 範例。
  • GitHub push protection：GitHub 可阻擋支援格式的 secret；這是最後防線，不是可以提交 .env 的理由。
  • OWASP Top 10 for LLM Applications 2025：敏感資訊揭露、prompt injection、過度代理、misinformation 等風險。
