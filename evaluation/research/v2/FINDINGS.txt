TrustLedger 詐欺偵測框架 v2
實驗結論

這是獨立研究實驗，沒有改動正式環境的警示決策。
沒有呼叫 Jev、Gemini 或 Backboard。

最重要的結論

在 BankSim、固定 919 筆人工審核的條件下，這次重新測到的三個結果是：

1. 現行金額／重複規則
   真陽性 701，假陽性 218，精確率 0.763，召回率 0.584，F1 0.662
   Average Precision 0.450

2. PR #14 的 mapped HistGradientBoosting，這次重新訓練
   真陽性 786，假陽性 133，精確率 0.855，召回率 0.655，F1 0.742
   Average Precision 0.815
   這兩個數字與 PR #14 存檔完全一致。它們是這次新跑出來的重現，不是把舊 JSON 抄進比較表。

3. 凍結規則選出的新模型 v2_merchant
   真陽性 892，假陽性 27，精確率 0.971，召回率 0.743，F1 0.842
   Average Precision 0.958

919 是固定名額。真陽性增加多少，假陽性就減少多少。
不要把「多抓 106 件」和「少誤報 106 件」當成兩件獨立的好事。

這個最大增幅的主因是訓練期的商家詐欺率。
它記住的是這套模擬器裡哪些商家常出現詐欺，不是一套可以換到新商家的行為模型。
因此我不建議在示範前把它接上正式警示。

若拿掉商家詐欺率，同一規則會留下 v2_enriched_sqrt。
它在同一 919 筆名額抓到 837 件詐欺、82 件誤報，Average Precision 0.885。
相對 PR #14，多抓 51 件。這個增幅小得多，而且仍然只在 BankSim 上成立。

594,643 筆，7,200 件詐欺，steps 0–179。

該切片上現行規則警示數的召回率較高。
確認切片只用來執行事先寫好的商家率門檻，不能改寫贏家。

這是對照用的保留集，不是未碰過的盲測。
BankSim 沒有更早、且完全沒被先前研究使用的時間切片。

Sparkov 本地檔不是官方資料，沒有拿來訓練或當驗證成績。

卡號是科學記號；unix time 從 1325376018 到 1362931730，約 2012-01-01 到 2013-03。

兩者不是同一份檔。

新架構

名稱：類別條件歷史梯度提升，外加一個商家率對照臂。

所有梯度提升模型共用 PR #14 的超參數，沒有做大範圍搜參：
max_iter 80，learning_rate 0.08，max_leaf_nodes 31，
min_samples_leaf 40，l2_regularization 0.1，random_state 20261017。

特徵只使用當時已經能知道的資訊：

- 金額的 log、客戶過去筆數、相對個人平均的金額、客戶 z 分數
- 對該客戶是否為新商家、距上一筆的步數
- 24 小時內同商家同金額的重複
- 同一步與近 7 步的筆數、近 30 步個人金額中位數比
- BankSim 原始類別，不是產品用的粗分類
- 訓練期合法交易算出的類別金額 CDF，以及相對類別中位數的倍數
- 對照臂才使用：訓練期商家詐欺率，向整體詐欺率收縮，alpha 20
- 另一個對照：相對該商家合法金額中位數的倍數，不用詐欺標籤

沒有使用年齡、性別、郵遞區號，也沒有把原始客戶或商家識別直接送進模型。
類別與商家統計只由 steps 0–119 估計。
客戶歷史只看更早的列。
同一天內的順序沿用檔案順序，與 PR #14 相同。

決策有兩層：

- 排序：分數高的優先，同分再看金額，供固定審核名額使用
- F1 閾值：只在 steps 120–134 上選，再套到後面的切片
- 理由碼是固定規則，不是語言模型

和現行系統的差異

現行規則是第一個命中的條件：24 小時同商家同金額，否則金額至少 250，
否則訂閱漲幅超過 20%。BankSim 沒有訂閱旗標，所以重現出來的規則只有前兩段。
信心分數固定是 1。

v2 不保留這條規則當最終決策。
金額規則仍是比較基準。實驗顯示它的排序能力遠低於梯度提升。

凍結規則的贏家是 v2_merchant。
它比最佳非商家率模型高 0.0605，超過 0.01 的複雜度容忍帶。
確認集差距是 0.0661，也超過事先定的 0.01。
因此部署門檻也把 v2_merchant 標成建議模型。
這個「建議」只代表它通過了事先寫好的分數門檻。
它不代表商家率可以換到新商家。見下方消融。

若依同一套平手規則、但排除商家詐欺率，留下的是 v2_enriched_sqrt。
商家合法金額比的驗證分數只高它 0.004，落在 0.01 以內，
而且特徵群更多，所以沒有贏過平手規則。

哪些想法成立，哪些不成立

成立，而且在確認集與測試集都還在：

- 保留 BankSim 原始類別。native weighted 的測試 Average Precision 是 0.8676，
  mapped HGB 是 0.8154。產品把多個高風險類別併成 other 之後，排序變差。
- 客戶自己的過去交易有用。拿掉歷史、只留金額與類別後，測試 Average Precision 降到 0.8074。
- 在相同 919 筆名額，分數模型會把名額分給更像詐欺的交易。

不成立，或增益小到不值得加複雜度：

- 類別金額 CDF 單獨使用，測試 Average Precision 0.564，比原始金額 0.704 差。
  很多詐欺的 CDF 都擠在 1 附近，金額大小的排序反而被壓扁。
- 類別詐欺率乘上 CDF，測試 Average Precision 0.639，仍然輸給原始金額。
- 把原生 HGB 和 CDF 做平均或取最大，都沒有贏過 HGB 本身。
- 很重的類別權重沒有提升排序。enriched 的 balanced 權重在驗證集是 0.890，
  不加權是 0.895，sqrt 權重是 0.896。差距在噪音帶裡。
- 公開筆記本常見的 Random Forest，只用 log 金額加原始類別，
  測試 Average Precision 0.799，919 筆名額抓到 773 件。
  它贏過現行規則，但沒有贏過 PR #14 的 HGB。
- 商家合法金額比沒有重現商家詐欺率的增幅。
  測試 Average Precision 0.880，和 enriched 幾乎一樣，遠低於 0.958。

商家率為什麼看起來很強

選擇集上的置換重要度，樣本是該切片全部 600 件詐欺再加 8,000 筆合法交易。
這個樣本的基準 Average Precision 是 0.989，高於完整驗證集的 0.957，
因為詐欺被抽得比較密。相對落差仍然很清楚：

- merchant_rate 拿掉後 Average Precision 下降 0.756
- 下一個特徵 amount_over_cat_median 只下降 0.020
- 速度、log 金額、CDF 都小於 0.005

訓練期有詐欺紀錄的商家有 30 個。
前 5 個商家佔訓練期詐欺的 59.75%。
測試集裡，沒在訓練出現過的商家是 0 筆。
訓練筆數少於 20 的商家只有 4 筆測試交易，而且都不是詐欺。
所以「新商家」這個健壯性檢查沒有材料，不能用來證明商家率會泛化。

BankSim 的商家集合在 180 步裡是封閉的。
時間切分擋得住未來交易，擋不住「同一個壞商家繼續出現」。

假陽性是 36、116、284。
308 件漏抓裡，203 件的類別 CDF 低於 0.90，140 件對該客戶是新商家。
漏掉的不全是小額，也不全是極端大額。

只有舊模型抓到 83 件，兩邊都沒抓到 225 件。

商家率把名額集中到訓練期就很髒的商家。
旅遊、家居、3C 這些沒有被同一批商家代表的詐欺，反而變容易漏。

919 筆警示裡，721 筆的類別 CDF 至少 0.95，646 筆金額至少 250，
357 筆對客戶是新商家，329 筆客戶 z 分數至少 3，43 筆同一步已有至少兩筆過去交易。
這些是警示人口的描述。置換重要度顯示，模型真正依賴的是商家率，不是這些理由碼。

新客戶切片不能解釋。測試集裡，訓練期沒出現過的客戶只有 3 筆、2 件詐欺。
這個數字沒有推論價值。

速度

整份歷史特徵約 52 秒。
v2_merchant 訓練 2.03 秒，預測約 0.49 毫秒／每千筆。
PR #14 HGB 訓練 1.65 秒，預測約 0.40 毫秒／每千筆。
公開 Random Forest 訓練 2.73 秒。
預測時間不含特徵擷取。單筆增量更新的延遲沒有另外測量。

建議

研究紀錄上的贏家是 v2_merchant。
示範前不要把它接進正式警示。

原因：

- 增益主要來自封閉商家集合上的詐欺率
- 測試商家全部都在訓練期出現過，轉移能力沒有被測到
- 測試時間段不是盲測
- 兩份資料都是模擬器。BankSim 的小偷是被放進去的，大約每步三張卡、每天約兩筆詐欺
- 訂閱規則在這份資料無法評估
- 金額尺度不能直接搬進示範資料

若示範後要做影子評分，先用不含商家詐欺率的 v2_enriched_sqrt，
而且只輸出分數與理由碼，不覆寫 needs_human、嚴重度或現行規則。
還必須用部署環境自己的金額分布重新校正，不能載入這份 BankSim 權重。

正式整合至少要改這些位置，而且現在不該改：

- 不改 backend/app/core/rules.py 的權威決策
- 新增一個隔離的評分器，輸入正規化交易與過去歷史
- 保留來源類別。若只送產品的粗類別，測試 Average Precision 會從約 0.868 掉回約 0.815
- 歷史儲存必須是過去資料，不能用整表聚合
- 商家詐欺率若將來要實驗，只能使用該商家在決策前已經確認的詐欺，
  而且要另做「沒看過的商家」測試。這次 BankSim 做不到這項測試
- 契約若要多回傳分數，需先和 integrator 同意，再改 API

最安全的示範策略是維持現行規則。
這份研究留在獨立分支，不合併。
