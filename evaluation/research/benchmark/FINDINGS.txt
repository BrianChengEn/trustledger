TrustLedger BankSim 公開模型對照
狀態：實測完成。這份文字只報告已寫入分數檔的測量。

一句結論
在同一份 BankSim、同一時間切分、同一個 919 筆審查預算下，
帶有商家歷史詐欺率的 TrustLedger v2_merchant 點估計最高（Average Precision 0.958485）。
把訓練列的標籤洩漏拿掉之後，step-causal 版本是 0.957628。
最強的公開完整管線是 0xSushmitha 的 LightGBM，Track B Average Precision 0.953491。
兩者的 Average Precision 差距在預先聲明的 0.01 接近帶裡。
顧客區塊與 step 區塊的信賴區間對「是否分得出來」給了不同答案，
所以這次不宣稱 TrustLedger 明確贏過這條公開管線。
在同一組、不含商家詐欺率也不含身份代碼的特徵上，
v2_enriched_sqrt 與 atavci 的 XGBoost logistic 打成平手。
大的差距來自商家身份，不是學習器品牌。


這次實驗是什麼

資料是 BankSim，本機檔案 /tmp/tl-eval-data/banks.csv。
594,643 筆交易，7,200 件詐欺，step 0–179。原始檔不進 git。
授權是 CC BY-NC-SA 4.0。

切分沿用 PR #15，而且在任何新的公開模型看到 test 分數之前就凍結在 contract.py：

TRAIN     steps 0–119    374,914 筆    4,800 件詐欺
SELECT    steps 120–134   53,722 筆      600 件詐欺
CONFIRM   steps 135–149   54,701 筆      600 件詐欺
TEST      steps 150–179  111,306 筆    1,200 件詐欺

steps 150–179 已經在 PR #14 與 PR #15 看過。
這次是可重現的架構對照。它是已被檢視過的 test 切分上的比較。
超參數在看這次 test 分數之前就凍結。公開模型的超參數來自原碼，
沒有用 SELECT、CONFIRM 或 TEST 的標籤來選模型。

主要排序鍵是完整 test 的 Average Precision（PR-AUC）點估計，由高到低。
預先聲明：Average Precision 差距在 0.01 以內，先稱為接近，
除非成對 bootstrap 的兩個區塊方法都把 0 排除在外。
Bootstrap 的平均數不重排榜單。
操作點是風險分數最高的 919 筆。平手時金額高的在前，再相同則列索引小的在前。
Accuracy 不用來選贏家。110,106 / 111,306 列是正常交易，
所以每個模型的 Accuracy 都落在 0.9936 到 0.9971。


PART A — 公開模型

短名單只有兩份可執行、而且架構確實不同的 BankSim 來源。
沒有任何一份接到本契約後仍是 FAITHFUL。
FAITHFUL 的意思是：接到已凍結的時間切分之後，仍逐字沿用原流程。
原文要嘛在切分前就對全表編碼，要嘛使用這份檔案上不存在的 step 切點。

入選 1。atavci / turkayavci，2019-03-15。
來源：
https://github.com/atavci/fraud-detection-on-banksim-data/blob/master/Fraud_Detection_bank_sim.py
Kaggle 頁：
https://www.kaggle.com/code/turkayavci/fraud-detection-on-bank-payments/notebook
這次 Kaggle 頁只回傳標題，cell 內文沒有讀到。實作以 GitHub 腳本為準。
架構：KNeighborsClassifier、RandomForestClassifier、
XGBClassifier(objective=binary:hinge)，再 VotingClassifier(voting=soft)。
權重 [1, 4, 1]，順序是 KNN、RF、XGB。
特徵：丟掉兩個 zip。customer、age、gender、merchant、category
在整個 frame 上做 pandas category code，然後才做打亂的分層切分
（test_size=0.3、random_state=42）。保留 step 與 amount。
超參數寫死在腳本裡。RF 是 n_estimators=100、max_depth=8、
class_weight=balanced、random_state=42。
XGB 是 max_depth=6、learning_rate=0.05、n_estimators=400、
其餘正規化與抽樣參數見 discovery/SHORTLIST.txt。
本契約的改寫：代碼只在 TRAIN 出現過的值上編，沒看過的值是 -1。
切分改成上面的時間切分。這兩點使它成為 ADAPTED。
binary:logistic 是契約預先聲明的排序改寫，用來產生連續分數。
它不是看過 test 之後才加的。hinge 仍照原文訓練，而且分開報告。

入選 2。0xSushmitha，2025-08-28，commit c2be9659。
來源：
https://github.com/0xSushmitha/Fraud-detection-in-financial-Transactions
訓練碼在 src/banksim_fraud/model.py。
架構：5 個 LGBMClassifier，n_estimators=300、learning_rate=0.07、
num_leaves=63、verbose=-1、random_state=200+k。
只對訓練列做 undersample，詐欺數 / 正常數 = 0.05。
分數是 5 個 predict_proba 的平均。
註解寫的 1:50 與 sampling_strategy=0.05 不一致。0.05 是約 1:20。
這次跟隨 0.05，抽樣用 NumPy Generator，不是 imblearn 的同一條亂數流。
他們的 README 寫 step<=600 訓練、step>600 測試，又把 step 寫成小時 1–740。
這份 canonical BankSim 的 step 只有 0–179，那個切點不存在。
features.py 的 rolling 視窗含當前列，沒有 README 寫的 shift(1)。
本契約的視窗不含當前列，也不含未來列。zip 是常數，已省略。
age、gender、category 的 one-hot 用 drop_first，類別順序是訓練集出現順序。
is_night = (step % 24) <= 5 是他們把 step 當小時留下的欄位。
這份檔案的 step 是日序，所以這個欄位沒有實體時間意義，仍照他們的定義保留，並標明。
這些改動使它成為 ADAPTED。
Optuna 搜索與 SMOTE 變體沒有採用。SMOTE 變體在切分前就擬合，不入榜。

沒有第三名。
aravind-sundaresan/Graph-ML-Fraud-Detection 有執行輸出，
但是 merchant one-hot 與 PCA 在全資料上擬合、沒有種子、還依賴 Neo4j。
不入榜。其餘公開頁面缺少可執行碼、用了別的資料集，
或公布的 FP/FN 彼此矛盾。名單與排除理由在 discovery/SHORTLIST.txt。
沒有為了湊滿 5 個模型而放入弱基線。

保真度
- atavci RF、XGBoost hinge、XGBoost logistic：ADAPTED。
- atavci soft vote：APPROXIMATION。
  時間門檻沒有強制略過 KNN。
  Track A 探測 0.529 秒，外推 552 秒。
  Track B 探測 0.027 秒，外推 28 秒。
  門檻是探測超過 60 秒，或外推超過 600 秒。
  訓練腳本仍沒有在 374,914 筆訓練列上擬合 KNeighborsClassifier。
  存下來的 ensemble 是 (4 * RF 機率 + 1 * logistic XGB 機率) / 5。
  原文權重是 [1, 4, 1]，分母應為 6，而且第一項是 KNN。
  這個近似把 RF 的權重從 4/6 改成 4/5。train_seconds 記 0，
  因為它重用已經訓練好的 RF 與 XGB，不是一個零成本模型。
  原文公布的 ensemble F1 0.77 低於單獨 XGBoost 的 0.82。
  在我們的 Track B 上，近似 ensemble 的 Average Precision 0.892527
  也低於 logistic XGBoost 的 0.921597。
  補上 KNN 不太可能改變榜首。這次沒有補跑，也沒有覆蓋這份近似。
- 0xSushmitha LightGBM：ADAPTED。
- TrustLedger 四個舊模型：TRUSTLEDGER_REPRODUCTION。
- v2_merchant_step_causal 與 v2_merchant_expanding：LEAKAGE_VARIANT。
  它們不是 PR #15 的逐字重現。


PART B — 實驗是否公平

16 個模型的 test 人口都是 111,306 列、1,200 件詐欺、919 筆警報。
獨立審計把 y、amount、step、customer、merchant、category 的指紋對過。
16 份檔案的六個指紋相同。assemble.py 的 alignment_problems 是空的。
contract.evaluate 與審計程式各自重算的 Average Precision 差額是 0。

兩條軌道沒有混在同一句話裡當同一個比較。

Track A，特徵對齊。
每個模型拿到同一組欄位：v2 enriched 數值欄、類別 CDF、
金額相對類別中位數、native category one-hot。
沒有 merchant fraud rate，沒有 age、gender、zip，也沒有原始 customer 或 merchant id。
模型仍可依自己的架構做轉換。atavci 與 Sushmitha 在這條軌道上
使用他們自己的學習器與抽樣，特徵集合則換成這組欄位。

Track B，公開完整管線。
atavci 使用 step、amount，以及 customer、age、gender、merchant、category 的訓練前綴代碼。
Sushmitha 另外使用過去視窗、顧客與商家的累計次數，以及上面的 is_night。
身份代碼在 Track B 是允許的。它們不是目標編碼。
代碼只在訓練列上擬合。

洩漏限制
- 沒有模型讀到當前列的 fraud 標籤來當特徵。
- 沒有模型用 SELECT、CONFIRM、TEST 的標籤來編 test 特徵。
  凍結商家率若被塞進這三個切分的標籤，test 列會全部改變。
  這是反事實。實際凍結特徵沒有用到它們。
- Sushmitha 的歷史視窗不含當前列與未來列。
- step-causal 商家率在 step t 的訓練列只用 step < t。同一步的標籤互不可見。
- expanding 是另一個資訊集，單獨成列，不拿來覆蓋重現結果。

TrustLedger 六個 JSON sidecar 沒有 leakage_status 欄位。
審計因此對它們記了 6 項 missing_leakage_status，程式退出碼 2。
完整性檢查通過。這是欄位缺口，不是分數錯誤。
洩漏結論寫在 trustledger/audit.json，沒有回改已經審計過的 sidecar 數字。

模型選擇
公開超參數凍結自原碼。TrustLedger 的 HGB 凍結自 PR #15：
max_iter 80、learning_rate 0.08、max_leaf_nodes 31、min_samples_leaf 40、
l2_regularization 0.1、random_state 20261017。
權重：pr14 是 balanced，v2_enriched_sqrt 是 sqrt，
v2_merchant 與兩個修正版是 none。
沒有模型在這次 test 上再做搜索。
公開模型沒有被故意換成較弱的預設值。
SELECT 與 CONFIRM 有算出分數，沒有用來改贏家。
以 Track B Sushmitha 為例，SELECT Average Precision 0.954703，
CONFIRM 0.947459。那兩個切分只有約 5.4 萬列，
仍切 919 筆時，審查率比 test 高，F1 不能跟 test 的 F1 比。

PART D — v2_merchant 可不可信

訓練程序裡，標籤洩漏是真的。
test 分數不是靠把 test 標籤送進特徵做出來的。

original_frozen 是 PR #15 的商家率。
公式是 (該商家訓練期詐欺數 + 20 * 全域率) / (該商家訓練筆數 + 20)。
聚合用全部 steps 0–119，然後填回每一列，包含提供這些標籤的訓練列。

1. 訓練列自己的標籤有進入特徵。
   拿掉該列再算，374,914 列的差距都大於 0。
   平均絕對差 1.9636312546803278e-05。
   詐欺列平均絕對差 0.0008757162664799481。
   最大絕對差 0.013641193354449077。
   單列的影響很小。收縮與商家筆數把它壓住了。

2. 較晚的訓練標籤有進入特徵。
   371,371 / 374,914 列會變。
   平均絕對差 0.0021280282910159445。
   最大絕對差 0.7779909302800466。
   訓練特徵是樂觀的。模型在擬合時看得到後來才發生的訓練期詐欺。

3. SELECT、CONFIRM、TEST 的標籤沒有進入凍結率。
   與只用 steps 0–119 重算的率，最大絕對差是 0.0。
   select_labels_included、confirm_labels_included、test_labels_included 都是 0。

4. step-causal 的 test 特徵與凍結率相同，最大絕對差 0.0。
   訓練特徵不同，最大絕對差 0.8320817163569871，374,914 列都不同。
   同一步的標籤互不可見。
   因此 0.957628 與 0.958485 的差異來自分別用兩套訓練特徵去擬合，
   test 當下看到的商家率向量是同一套 steps 0–119 聚合。
   兩個區塊的 Average Precision 與 TP 信賴區間都含 0。
   0.958 不是 test 列洩漏製造出來的數字。
   引用架構時仍用 step-causal，因為訓練程序比較乾淨。
   0.958485 保留為 PR #15 的逐字重現，不把它從表上刪掉。

5. expanding 的 test 特徵不同。
   每一列只用已經結束的較早 step。
   test 列看得到 steps 120–149，也看得到更早的 test step。
   與凍結率不同的 test 列是 111,306，最大絕對差 0.1795012931979003。
   Average Precision 0.956777，TP 897。
   這是另一個資訊集。它不是洩漏修正，也不是 PR #15 的重現。
   它的點估計還略低於凍結版。

6. BankSim 沒有標籤延遲欄位。
   凍結版假設 steps 0–119 的標籤在 step 120 之前都已知道。
   expanding 假設一個標籤在該 step 結束時可知、下一步之前可知。
   兩種修正都不讓同一步的標籤互相看見。
   這是假設，不是資料裡的事實。

7. 這個切分不能評估沒見過的商家。
   test 未見過的 merchant id：0。
   落在未見過商家的 test 列：0。
   訓練筆數少於 20 的 test 列：4，其中詐欺 0。
   訓練筆數至少 20 的 test 詐欺：1,200。
   訓練裡 50 個 merchant id 有 30 個出現過詐欺。
   前 5 名商家占訓練詐欺的 0.5975。
   不要把這個結果寫成新商家泛化。

商家率貢獻了多少
v2_merchant 0.958485 減 v2_enriched_sqrt 0.885260，約 0.0732。
同一套 HGB、同一個切分，差在商家率欄位與權重（sqrt 對 none）。
Track B Sushmitha 0.953491 減 Track A Sushmitha 0.881686，約 0.0718。
同一族學習器，差在身份代碼與過去歷史。
atavci logistic 的代碼本身，Track B 0.921597 減 Track A 0.884441，約 0.0372。
沒有 rolling 視窗。
三個對照指到同一件事：商家身份帶著大的增益。
學習器在對齊特徵上的差距落在噪音裡。

v2_enriched_sqrt 還有沒有競爭力

PART E — 結論

TrustLedger 有沒有勝過重現出來的公開架構

在完整管線上，點估計的第一名是 v2_merchant。
洩漏修正後的 step-causal 仍略高於 Sushmitha Track B，
差距約 0.004，在 0.01 以內，而且兩種區塊方法不一致。
不宣稱明確獲勝。
對 atavci 的 Track B XGBoost logistic，差距是明確的：
Average Precision 約高 0.037，919 筆約多 32 到 35 件 TP。
這份優勢綁在商家詐欺率上。

在特徵對齊的軌道上，TrustLedger 沒有勝過公開模型。
v2_enriched_sqrt 與 atavci XGBoost logistic 打成平手。

技術差異
- 商家歷史詐欺率，或身份代碼加過去歷史，解釋了大約 0.04 到 0.07 的 Average Precision。
- HistGradientBoosting、XGBoost、LightGBM 在同一組對齊特徵上接近。
- 規則只靠金額門檻與 24 小時同商家同金額重複。
  它抓到全部金額 >=250 的詐欺，也因此填進大量高額正常交易。
- Hinge 沒有連續分數。操作點因金額平手而接近 logistic，
  ROC-AUC 則掉到約 0.86。
- 高額詐欺大家都抓得到很多。中額與 es_health、es_sportsandtoys
  是商家率與 Sushmitha 歷史拉開差距的地方。
- 小額詐欺仍然大多漏掉。
- 前 5 個商家占了 710 / 1,200 件 test 詐欺。結果對商家組成敏感。

證據支持的架構
若允許重複出現的商家，而且接受歷史詐欺率或身份代碼：
step-causal 的商家率 HGB，與 Sushmitha 的身份加歷史 LightGBM，
是同一性能帶。兩者都強。
若示範流程不使用商家詐欺率與原始身份：
v2_enriched_sqrt 是目前證據支持的 TrustLedger 候選。
它與同一特徵上的 XGBoost logistic 打成平手。
不要把「我們的模型贏了 Kaggle」寫進對外說明。
對外能說的是：在這份已被看過的時間切分上，
商家身份決定大的差距，對齊特徵之後現有 HGB 與強的公開 booster 相當。
